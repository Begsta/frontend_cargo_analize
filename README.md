# Расчёт производительности башенного крана

Лабораторная работа №5: базовое SPA на React и TypeScript.
Интерфейс предназначен для гостевого просмотра грузов: панелей,
балок и фундаментных блоков с массой, габаритами и объёмом.

Используются Vite, React-Bootstrap, Bootstrap и React Router.
Оформление перенесено из предыдущих лабораторных: WOLFF,
белый фон, красные акценты и мобильная рамка шириной до 430 px.

## Запуск

Рекомендуется Node.js 22 LTS и npm.
Из папки `frontend_cargo_analize` выполните:

```bash
npm install
npm run dev
```

Откройте адрес из терминала, обычно `http://localhost:5173`.
Для проверки типов и production-сборки:

```bash
npm run build
```

Для просмотра собранного приложения:

```bash
npm run preview
```

## Страницы, кнопки и поля

### Лента — `/`

На экране показан один груз: видео, название, масса, объём
и информационный счётчик интереса. Данные взяты из mock-коллекции.

- «Описание груза» раскрывает текст на месте и сворачивает его.
- «Далее» открывает следующий груз; после последнего — первый.
- `/?cargo=ID` открывает груз, выбранный в плитке.
- `/cargo/:id` отображает ту же ленту с указанным грузом.

### Плитка — `/catalog`

Карточки показывают изображение, название, массу, объём
и информационный счётчик интереса.

- Ползунок «Масса, т»: диапазон от 0 до 10, шаг 0,1 т.
- Число справа показывает выбранную массу.
- «Отобрать» применяет фильтр по минимальной массе.
- Значение 0 показывает все грузы.
- Нажатие карточки открывает выбранный груз в ленте.

Перемещение ползунка не меняет выдачу до нажатия «Отобрать».
Если подходящих грузов нет, выводится сообщение.

### Добавление — `/cargo_addition`

Экран повторяет страницу добавления из предыдущей лабораторной.
Его можно открыть напрямую для демонстрации третьей страницы.

- Показаны изображение и видео по умолчанию.
- У видео доступны стандартные элементы управления.
- Поля выбора изображения и видео отключены.
- Поле «Наименование груза» и кнопка «Далее» отключены.

Создание груза и отправка данных не реализованы.
ТЗ требует три страницы, но назначение третьей не уточняет.
Для неё выбран существующий экран добавления; отключение полей
является решением этой реализации, а не отдельным требованием ТЗ.

## Нижняя навигация

- «Лента» — доступна.
- «Добавление» — отключено.
- «Плитка» — доступна.
- «Вход» — отключён.

Активный доступный пункт выделен красным.

## Mock-данные и медиа по умолчанию

Все девять грузов находятся в `src/data.ts`.
Запросов к API нет: фильтрация и переключение выполняются
в браузере. Redux и Context в коде приложения не используются.

При пустом поле `image` используется локальное изображение
`public/media/default-cargo.jpg`. При ошибке загрузки изображения
компонент `Media` также подставляет этот файл.

При пустом поле `video` используется локальное видео
`public/media/default.mp4`. В mock-записях оба поля пустые,
поэтому можно показать подстановку медиа без изменения кода.

В Network видны загрузки HTML, модулей, стилей и локальных медиа.
В режиме разработки также возможно соединение Vite для обновлений.

В формулировке задания есть противоречие: вводная упоминает
подключение сервиса, а подробная часть требует только mock-данные
без бэкенда. Здесь выполнено требование подробной части.

## Компоненты и props

- `CargoCard` получает `cargo` и отображает карточку груза.
- `Media` получает `cargo` и отображает его изображение.
- `CargoFilters` получает выбранную массу `value`, обработчик
  изменения `onChange` и обработчик применения `onApply`.
- `Catalog` хранит выбранную и применённую массы и передаёт
  значения и обработчики в `CargoFilters`.

Props передаются от родителя к дочернему компоненту.
Фильтр вызывает обработчики родителя, не изменяя props напрямую.

## Используемые хуки

- `useState` в `Catalog`: выбранная и применённая массы.
- `useState` в `Media`: признак ошибки загрузки изображения.
- `useEffect` в `Media`: сброс ошибки при изменении зависимостей
  `[cargo.id, cargo.image]`.
- `useEffect` в `App`: установка заголовка документа;
  массив зависимостей пустой.
- `useParams` в `Feed`: чтение ID из `/cargo/:id`.
- `useSearchParams` в `Feed`: чтение и изменение параметра `cargo`
  для переключения грузов без перезагрузки страницы.

## Структура исходников

- `src/main.tsx` — запуск React и подключение стилей.
- `src/App.tsx` — маршруты и заголовок документа.
- `src/data.ts` — тип груза, mock-данные и вычисление объёма.
- `src/pages/` — лента, плитка и экран добавления.
- `src/components/` — карточка, фильтр, изображение и навигация.
- `src/style.css` — стили интерфейса.

Строки исходного кода не превышают 72 символов.
Настройки отступов и длины строк указаны в `.editorconfig`.

## Контрольные вопросы

**React** — библиотека декларативного построения интерфейса
из компонентов.

**Компонент и элемент.** Функциональный компонент описывает,
как построить часть интерфейса. React-элемент — объект,
описывающий узел интерфейса; такие элементы создаются через JSX.

**Props и состояние.** Props — входные данные от родителя.
Состояние — данные, которыми управляет компонент. Вызов функции
обновления состояния планирует повторный рендер.

**useState и useEffect.** Первый хранит состояние компонента.
Второй синхронизирует компонент с внешними системами после
фиксации рендера. Функция очистки эффекта, если она возвращена,
вызывается перед повторным запуском эффекта и при размонтировании.

**Жизненный цикл.** Монтирование, обновление и размонтирование.
В режиме разработки StrictMode дополнительно проверяет эффекты
циклом установки и очистки.

**Vite и Babel.** Vite предоставляет сервер разработки и сборку.
Babel преобразует синтаксис JavaScript и JSX, но не проверяет типы
TypeScript. В этом проекте Babel отдельно не подключён;
типы проверяет `tsc`, преобразование и сборку выполняет Vite.
