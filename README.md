# WOLFF — расчёт производительности башенного крана

Лабораторная №6: завершение интерфейса пользователя в React.
Ветка: `lab6-redux-api-auth`, создана от `feat/spa` лабораторной №5.
Сохранены оформление WOLFF, мобильная рамка 430 px, лента и плитка.
Предметная область интерфейса — строительные грузы для башенного крана.

## Запуск

Использовать Node.js 22.12+ и npm (в том числе для обновлённого Vitest).

```bash
cd /home/honor/web/frontend_cargo_analize
npm install
npm run dev
```

Открыть адрес Vite, обычно http://localhost:5173.

```bash
npm run api:generate
npm test
npm run build
```

Для гостевого показа mock бэкенд не нужен. При сетевой ошибке или ответе
5xx методы чтения используют коллекцию из лабораторной №5.
У авторизованного пользователя такой подмены нет. Ответы 4xx также
не заменяются mock-данными: например, отсутствие черновика — это 404.
При отсутствии доступа к API запрос ожидает ответ до 10 секунд.

Для работы с сервисом в другом терминале:

```bash
cd /home/honor/web/backend_cargo_analize
docker volume create web_minio-data
docker compose up -d --build
.venv/bin/alembic upgrade head
.venv/bin/python main.py
```

Окружение Python и `.env` подготавливаются по README бэкенда.
Для входа заранее зарегистрировать пользователя в Swagger:
http://127.0.0.1:8000/docs → `POST /api/users`.
Форма регистрации во фронтенд не добавлена.

## Четыре страницы

| Страница | Маршрут | Поведение |
|---|---|---|
| Лента | `/`, `/?cargo=ID`, `/cargo/:id` | Видео, описание, масса, объём, счётчик, следующий груз; пользователь ставит/снимает лайк и удаляет свой груз |
| Плитка | `/catalog` | Изображения, характеристики, фильтр минимальной массы; пользователь удаляет свой груз |
| Добавление | `/cargo_addition` | После входа создаёт черновик с названием, фото и видео, затем публикует его с характеристиками |
| Вход | `/login` | Логин и пароль существующего пользователя |

Для гостя добавление в нижней панели отключено, доступна кнопка «Вход».
После входа добавление доступно, «Вход» заменяется на «Выход».
На прямом адресе добавления гостю предлагается войти.

Ползунок массы: 0–10 т с шагом 0,1. Перемещение меняет выбранное значение,
«Отобрать» применяет фильтр и отправляет `cargo_mass` на бэкенд.
В mock при 0 т видны 9 грузов, при 2 т — 6, при 10 т — ни одного.
Габариты и вычисление объёма mock сохранены; для сервиса используется
объём из БД. Отсутствующая характеристика показана знаком «—».

В добавлении «Далее» отправляет `cargo_name`, `image`, `video` как multipart.
Фото: JPG, PNG, WebP, GIF; видео: MP4, WebM, MOV. Сервер ограничивает
каждый файл 30 МиБ. После создания черновика заполняются описание,
масса и объём; «Опубликовать» выполняет PUT и открывает каталог.
Если черновик уже есть, страница загружает его вместо создания второго.

Пока идут AJAX-запросы, показывается анимация загрузки с блокирующим
слоем и отключаются кнопки действий. При ошибке выводится сообщение.
После удаления каталог обновляется, счётчик и личный лайк обновляются
по ответу сервера. Удаление показывается только владельцу по `is_creator`.
Окончательную проверку прав выполняет бэкенд.

## Redux Toolkit и thunk

`src/store/store.ts` создаёт store и slice интерфейса:

| Состояние | Назначение |
|---|---|
| `user` | Пользователь или `null` для гостя |
| `authPending` | Ожидание входа/выхода |
| `filters.mass` | Выбранная масса |
| `filters.appliedMass` | Применённая масса для запроса |
| `catalog`, `feed`, `draft` | Список грузов, текущий груз и собственный черновик |
| `requests` | Идентификаторы ожидаемых запросов |
| `error` | Сообщение ошибки |

`configureStore` подключает стандартный middleware Redux Toolkit,
включая thunk. Redux DevTools позволяет показать значения и действия.
Thunks названы по теме: `loadCargos`, `loadCargoFeed`, `nextCargo`,
`loadCargoDraft`, `createCargoDraft`, `publishCargo`, `deleteCargo`,
`setCargoInterest`. Они вызывают сгенерированный Axios-клиент.
`pending`, `fulfilled`, `rejected` управляют ожиданием, данными и ошибками.
Идентификаторы запросов не позволяют старому ответу заменить более новое
состояние или восстановить персональные данные после выхода.

Вход в `Login.tsx` и выход в `BottomNavigation.tsx` выполняются Axios
напрямую. Состояние меняется вручную через dispatch, без thunk
и сгенерированных методов авторизации.

При выходе сбрасываются фильтр, пользователь и персональные данные.
Ошибка выхода не считается успешным завершением серверной сессии.
401 защищённого запроса переводит интерфейс в состояние гостя.

## F5, cookie и Application

Состояние Redux не сохраняется в localStorage. После F5 создаётся новый
store с `user=null`: интерфейс гостевой, даже если серверная cookie ещё есть.
Автоматического восстановления авторизации нет — это сценарий методички.

Бэкенд использует сессию Redis, cookie называется `session_id`, имеет
HttpOnly и SameSite=Lax. Пароль и токен не записываются в localStorage.
HttpOnly запрещает чтение cookie JavaScript-кодом, но её можно увидеть
в DevTools → Application → Cookies и вручную использовать в Postman.

Браузер продолжает отправлять cookie с запросами через proxy после F5.
Поэтому сервер может возвращать `is_creator=1`, но гостевой интерфейс
не показывает кнопки удаления и не разрешает действия пользователя.
После повторного входа меню и действия переключаются в пользовательские.

## Кодогенерация Axios из Swagger / OpenAPI

`src/api/openapi.json` — сохранённая схема настоящего приложения FastAPI.
`scripts/generate-api.mjs` генерирует из неё типы и методы запросов
в `src/api/generated/cargoApi.ts` с использованием Axios.
Это локальный генератор: он читает параметры, тела, ответы и схемы
операций грузов из OpenAPI. Сгенерированный файл вручную не редактируется.
Авторизация использует ручные вызовы Axios вне сгенерированного клиента.

```bash
npm run api:generate
```

Чтобы обновить схему из текущего бэкенда без подключения к БД и Redis:

```bash
cd /home/honor/web/backend_cargo_analize
.venv/bin/python -c 'from main import app; import json; print(json.dumps(app.openapi(), ensure_ascii=False, indent=2))' > ../frontend_cargo_analize/src/api/openapi.json
cd ../frontend_cargo_analize
npm run api:generate
```

Для генерации из запущенного сервиса схему можно получить с
http://127.0.0.1:8000/openapi.json и сохранить в тот же файл.
Методы грузов называются по теме; например, thunk `loadCargos`
вызывает сгенерированный `getCargos({ cargo_mass: ... })`.
Файлы передаются через сгенерированную сборку `FormData`.

## Proxy для API и MinIO

`vite.config.ts` задаёт два маршрута сервера разработки:

| Адрес в браузере | Назначение |
|---|---|
| `/api/...` | `http://127.0.0.1:8000/api/...` |
| `/s3/...` | `http://127.0.0.1:9100/...` |

Axios использует относительные адреса и `withCredentials: true`.
Браузер обращается к origin фронтенда, Vite пересылает запрос сервису.
Для известных локальных адресов MinIO функция `mediaUrl` заменяет
origin на `/s3`, сохраняя имя бакета и объекта. Видео идут тем же маршрутом.
В JSON ответа API остаются исходные `image_public_url` и `video_public_url`.
Если изображения нет или его загрузка не удалась, используется локальное
изображение из №5; при пустой ссылке видео используется локальное видео.

Настройка proxy предназначена для `npm run dev`; статический production
хостинг требует таких же маршрутов на reverse proxy.
