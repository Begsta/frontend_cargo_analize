# Лабораторная №6 — порядок показа

Сначала запустить только фронтенд через `npm run dev`.
Для остальных шагов запустить бэкенд и его хранилища по README.
Использовать один адрес фронтенда, например `http://localhost:5173`.
Если до начала показа уже был выполнен вход, нажать «Выход» при работающем
сервисе, затем остановить только процесс FastAPI для первых двух кадров.

| № | Что показать |
|---|---|
| 1 | Без сервиса: `/catalog`, девять mock-грузов при массе 0; можно применить 2 т и получить шесть. Дождаться завершения запроса. |
| 2 | Без сервиса: `/`, mock-видеолента, описание, «Далее». |
| 3 | С сервисом: `/catalog`, реальные записи PostgreSQL и AJAX-запрос списка. |
| 4 | С сервисом: лента выбранного реального груза и его медиа. |
| 5 | `/login`, вход существующим пользователем. Для создания пользователя предварительно использовать Swagger `POST /api/users`. |
| 6 | `/cargo_addition` после входа: название, фото, видео → «Далее», затем характеристики → «Опубликовать». Можно показать существующий собственный черновик. |
| 7 | В Adminer изменить название и массу одного тестового опубликованного груза. Записать прежние значения. |
| 8 | На фронтенде обновить каталог: изменённые название и масса; фильтр использует новое значение. |
| 9 | После входа обновить страницу F5: меню «Вход», Redux `user=null`; в Application → Cookies остаётся `session_id`. Не нажимать «Выход» перед этим кадром. |
| 10 | Скопировать значение session_id из Application в Postman/Insomnia. `GET http://127.0.0.1:8000/api/cargos`, заголовок `Cookie: session_id=<значение>`. Для опубликованного груза этого пользователя показать `is_creator=1`. |
| 11 | Redux DevTools: `user`, `authPending`, `filters`, `catalog`, `feed`, `draft`, `requests`, `error`; изменения при фильтрации, запросе, входе и выходе. |
| 12 | Генератор `scripts/generate-api.mjs`, схема `src/api/openapi.json`, вызов Axios `http.request` в сгенерированном клиенте. Выполнить `npm run api:generate`. |
| 13 | Thunk `loadCargos`: вызов сгенерированного `getCargos` с `cargo_mass`, pending/fulfilled/rejected. |
| 14 | Тематические thunk создания/публикации/удаления/лайка и соответствующие сгенерированные методы. Вход и выход показать отдельно: ручные Axios и dispatch. |
| 15 | Network → Fetch/XHR: Request URL на origin Vite `/api/cargos?...`, затем `vite.config.ts` с proxy. |
| 16 | Response списка с именем объекта и `image_public_url` MinIO; Network → Img/Media: `/s3/cargo-media/<имя>`, второй маршрут proxy. Использовать груз с реально загруженным фото. |

## Изменение записи в БД

Adminer: http://localhost:8080. Система PostgreSQL, сервер `postgres`,
пользователь `cargo`, база `cargo_db`, пароль из docker-compose бэкенда.
В таблице `cargos` выбрать один тестовый опубликованный груз.
Изменить `cargo_name` и `cargo_mass`, сохранить. Для кадров 7–8 достаточно
двух этих полей. Запомнить или записать прежние значения для возврата.

## Дополнительные действия в рамках задания

- Войти снова после кадра F5, проверить меню «Выход» и доступность добавления.
- На своём опубликованном грузе показать «Удалить» в плитке и ленте;
  у чужого груза кнопки нет.
- В ленте поставить и снять лайк, показать изменение счётчика.
- Применить фильтр, нажать «Выход»: выбранная и применённая массы равны 0.
- При запросах показать анимацию и невозможность повторного нажатия кнопок.

Cookie в Postman передаётся вручную только для учебной демонстрации.
Наличие cookie после F5 и гостевой Redux — ожидаемые разные состояния.
HttpOnly не позволяет получить cookie через `document.cookie`.
В проекте нет JWT: демонстрируется существующая сессия Redis.
Для `is_creator=1` нужен именно опубликованный груз этого пользователя;
чужой груз или собственный черновик не подходят.

Список выше — сценарий получения настоящих скриншотов, а не утверждение,
что кадры уже сняты. Скриншоты создавать во время собственного запуска.
