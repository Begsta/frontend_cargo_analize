# Лабораторная №6 — контрольные вопросы

## Redux Toolkit: reducer, store, middleware

Store хранит состояние приложения. Компонент отправляет action через
`dispatch`. Middleware обрабатывает действие до reducer; thunk middleware
позволяет передавать функцию, выполняющую асинхронную работу.
Reducer вычисляет новое состояние по предыдущему состоянию и действию.
Подписанные компоненты получают новые данные через selector.

Схема: компонент → dispatch → middleware → reducer → store → selector
→ обновление компонента. `configureStore` создаёт store со стандартными
middleware. `createSlice` объединяет reducer и action creators.
В reducer Toolkit можно писать изменения полей благодаря Immer:
исходное состояние при этом не изменяется напрямую.

`createAsyncThunk` создаёт действия pending, fulfilled и rejected.
Запрос выполняется внутри thunk, результаты обрабатываются reducer.
В проекте используются thunk грузов; вход и выход по заданию выполняются
Axios напрямую с ручным dispatch. Redux DevTools показывает состояние
и последовательность действий.

## Axios

HTTP-клиент с Promise, настройками baseURL, параметрами запросов,
обработкой ответов и ошибок. Может передавать JSON и FormData.
В проекте Axios-клиент использует относительные адреса через proxy,
таймаут и `withCredentials`. Методы грузов генерируются из OpenAPI;
ручной код thunk вызывает эти методы, не повторяя адреса запросов.

## Local storage

Хранилище строк по origin в браузере. Сохраняет данные между перезагрузками,
доступно JavaScript через getItem/setItem/removeItem. Объекты нужно
сериализовать, например JSON.stringify. В отличие от cookie, данные
localStorage автоматически не отправляются в HTTP-запросах.

В этой работе Redux не сохраняется в localStorage: по заданию F5 возвращает
интерфейс гостя. Сессия остаётся в HttpOnly cookie, которую отправляет
браузер. Значение видно вручную в Application, но недоступно JavaScript.

## CORS и обратный прокси

Origin состоит из схемы, хоста и порта. CORS — механизм разрешений
браузера на чтение ответа от другого origin; он не заменяет авторизацию.
Прямое обращение с localhost:5173 к localhost:8000 является cross-origin.

Reverse proxy принимает запрос браузера на адрес фронтенда и пересылает
его внутреннему сервису. В работе Vite пересылает `/api` в FastAPI,
а `/s3` в MinIO. Браузер видит один origin. В production такие правила
нужно настроить на сервере размещения, например Nginx.

## BFF и GraphQL

BFF (Backend for Frontend) — серверный слой, специально подготовленный
под потребности конкретного интерфейса. Может объединять вызовы сервисов
и адаптировать ответы. Обычный Vite proxy только пересылает запросы
и не реализует такую агрегацию.

GraphQL — язык запросов и серверная среда их выполнения над типизированной
схемой. Клиент выбирает необходимые поля; чтение описывается query,
изменение — mutation. В текущем проекте используется HTTP API FastAPI,
а BFF и GraphQL рассматриваются как контрольные вопросы.

## Next.js и SSG

Next.js — фреймворк React с маршрутизацией и средствами серверного
рендеринга, статической генерации и серверной логики.
SSG — генерация HTML заранее, обычно при сборке, с последующей отдачей
готовых страниц. Подходит для содержимого, которое не требует получения
персональных данных на каждый запрос.

Текущий проект — React SPA с Vite. Команда vite build собирает ресурсы,
но сама по себе не генерирует отдельный HTML с данными для каждого груза.
Next.js и SSG в эту лабораторную не добавляются.

## FSD

Feature-Sliced Design — подход к организации фронтенда по слоям
ответственности и функциональным срезам. Типичные слои: app, pages,
widgets, features, entities, shared. Более высокие слои используют нижние;
срезы группируют код по предметному смыслу.

В работе сохранена структура из №5: pages, components, data; добавлены
api и store для требований №6. Полная перестройка по FSD не выполняется:
в задании требуется ответить на вопрос, а не провести такую миграцию.
